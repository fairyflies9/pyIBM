# Heaving plate, the 2008 MATLAB case

The case my 2008 MATLAB code (`matlab-original/move-plate-example/`) ran: a flat plate of
16 target points, half the box tall, that is pushed sideways through a very viscous fluid in
a doubly periodic box. It is here as the regression anchor of pyIBM:
`tests/test_matlab_regression.py` runs this directory through the driver and compares the
velocity, pressure, force and plate positions with the state the unmodified MATLAB code
saved at steps 1, 2, 3, 5, 10, 25, 50 and 100 (`tests/data/heaving_plate_2008_stiff1.mat`,
`..._stiff1e4.mat`, produced by `tests/data/generate_matlab_reference.m` in MATLAB R2024a).
The measured relative differences are about 1e-15; the test demands 1e-10.

## Physics and parameters

| quantity | value |
|---|---|
| box | 0.4 m x 0.4 m, doubly periodic, 16 x 16 cells, dx = 0.025 m |
| fluid | rho = 2 kg/m^2, mu = 3 N s/m^2 (nu = 1.5 m^2/s) |
| plate | 16 points at x = 0.2, y = 0.1 + i 0.0125, i = 0..15; ds = 0.0125 m = dx/2 |
| motion | every target at x_T(t) = 0.2 + 0.05 sin(2 pi t/10) m, y fixed (`hooks.py`, the `moveplate.m` law) |
| time step | dt = dx^2/nu = 0.025^2/1.5 = 4.1666666666666675e-4 s, evaluated as MATLAB evaluates it |
| length | 100 steps (t = 0.0417 s); the original ran to 10 s |
| output | every 5 steps to `viz/<variant>/` |

The Reynolds number is tiny (U L/nu with U = 0.03 m/s, L = 0.2 m gives 0.004): the plate
is dragged through syrup. The CFL number in `history.csv` stays below 1e-3 (largest 9.1e-4,
in the stiff runs).

Three inputs, all generated by `generate.py` (the stiffness lives in the `.target` file, so
there are two structures, `plate` with k = 1 and `plate_stiff1e4` with k = 1e4):

| input | stiffness k [N/m per m] | scheme | kernel | what it is |
|---|---|---|---|---|
| `input2d` | 1 | `pm1996` | `cosine4` | the 2008 settings |
| `input2d_stiff1e4` | 1e4 | `pm1996` | `cosine4` | the 2008 scheme and kernel with a stiffer tether, so the plate follows its path |
| `input2d_midpoint` | 1e4 | `midpoint` | `peskin4` | the setup we recommend in pyIBM: second-order scheme, kernel with the first-moment condition |

`pm1996` is the first-order scheme of Peskin & McQueen 1996 section 14 (upwind advection,
backward Euler, FFT projection); `cosine4` is Peskin's 1977 cosine kernel, which conserves
force but does not interpolate linear fields exactly (`docs/numerics.md`, kernels). The
tether number k dt^2/(rho dx) is 3.5e-2 at k = 1e4, far below 10, the value above which the
driver prints its rule-of-thumb warning for target points.

## How to run

```
python -m pyibm run examples/heaving_plate_2008
python -m pyibm run examples/heaving_plate_2008 --input input2d_stiff1e4
python -m pyibm run examples/heaving_plate_2008 --input input2d_midpoint
python examples/heaving_plate_2008/analyze.py
```

`analyze.py` reads `viz/*/history.csv`, prints the stiffness next to the largest target
error in cells for every variant that has been run, and saves `results.png` (target error
and x force on the plate against time). The force is plotted at its own time level, the
`t_force` column of `history.csv`: one step before the row's `t` for `pm1996` and half a
step before it for `midpoint`. `python generate.py` rewrites the structure and input files
(deterministic; the generated files are committed, and the tests check them byte for byte).

## What to expect

Measured on this machine (100 steps, output every 5 steps, 21 history rows). The force
columns are the `fx_body` of the history rows at `t = 0.01875 s` (step 45) and
`t = 0.0417 s` (step 100):

| input | max target error [cells] | fx on the plate, row t = 0.01875 s | row t = 0.0417 s |
|---|---|---|---|
| `input2d` (k = 1) | 0.052 | -1.15e-4 N | -2.6e-4 N |
| `input2d_stiff1e4` | 0.016 | -0.68 N | +0.079 N |
| `input2d_midpoint` | 0.016 | -0.68 N | +0.085 N |

With k = 1 the tether force stays small and the plate hardly moves: the fluid speed reaches
only 2.1e-5 m/s by t = 0.0417 s, and the force grows linearly from zero with the distance
the targets have travelled. The "target error" is that same distance, also growing linearly.
k = 1 is the value in the 2008 code, and we keep it so that the regression test runs that
code as it was. pyIBM adds the runs with k = 1e4, a stiffer tether, so the plate follows
its prescribed path.

With k = 1e4 the plate follows the targets to within 0.016 cells. The x force is the
fluid's reaction to the impulsive start: it grows to -0.68 N as the plate gets up to speed
and then relaxes as the fluid in the periodic box starts moving with the plate (the box
mean velocity is free to accelerate; `remove_mean_force` is off, as in 2008).

Row for row, the two stiff runs differ by up to 0.013 N, 1.9 % of the peak force, largest
in the first steps. Most of that is the time level of the force, not the force itself: a
`pm1996` row holds the force at `t - dt` and a `midpoint` row the force at `t - dt/2`, and
at the start the force grows by 0.026 N per step. In the row of step 1, `pm1996` has 0 N
(the force at t = 0) and `midpoint` has -0.0131 N (the force at dt/2). Compared at the same
`t_force`, the two runs differ by at most 0.0033 N, 0.49 % of the peak, at the end of the
run. Swapping only the kernel changes the force by 2e-6 of the peak: the plate points start
at whole and half cell offsets from the nodes, where `cosine4` and `peskin4` have the same
weights, and they move only about 0.05 cells in 100 steps. So the 0.49 % is the time
scheme. A quarter of the time step changes the force at its own time level by 0.38 % of the
peak with `pm1996` and by 0.014 % with `midpoint`. The midpoint run has converged in time,
and the 0.49 % is the first-order error of `pm1996`: going to dt/4 removes three quarters of
a first-order error, and 0.38 % is three quarters of 0.5 %.

Run time: 0.1 to 0.2 s for each input (100 steps on a 16 x 16 grid, laptop). The
regression test takes about a second.

## Files

- `generate.py`: writes `plate.vertex`, `plate.target`, `plate_stiff1e4.vertex`,
  `plate_stiff1e4.target` and the three input files.
- `hooks.py`: `update_targets` with the 2008 motion law as a function of absolute time.
- `analyze.py`: the comparison plot.
- `tests/examples/test_heaving_plate_2008.py`: smoke runs of the three inputs, a check that
  the committed files match `generate.py` byte for byte, the three full runs against the
  table above, the two stiff runs compared row for row, at the same `t_force`, at dt/4 and
  with the kernel swapped (all always on; each run takes a fraction of a second), and a slow
  test of the second-order run.
